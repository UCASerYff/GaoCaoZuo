# 搞桌面、搞锁屏收拢迁移契约

适用接收方为搞操作。来源源码、程序、真实资料、钥匙串、偏好及备份均只读；本文不代表安装、发布、真实迁移或来源退役已经完成。

## 来源格式与现物盘点

2026-11-02 只读检查发现，搞桌面正式安装身份为 `com.gaoseries.GaoZhuoMian`，V1.00 / build 1。业务配置使用 `~/Library/Application Support/GaoSeries/GaoZhuoMian/preferences.json`，独立初始化依据为相邻的 `GaoZhuoMian-Initialization.json`。`GaoZhuoMian-Backups` 有首装备份；历史备份不因此被视为当前真实资料的完整备份。

来源设置是 schema 1 的 `{payload, sha256}`。payload 含 `schemaVersion`、`storeID`、`generation`、`migrationHistory`、`preferences`；marker 含 `schemaVersion`、`storeID`、`createdAt`。两个 storeID 必须相等，generation 必须大于零。来源摘要使用 JSONEncoder 的 prettyPrinted、sortedKeys、withoutEscapingSlashes 和 ISO8601 日期编码重算。

preferences 的完整字段为 `appearance`、`thumbnailsEnabled`、`excludedThumbnailBundleIDs`、`hotkeyEnabled`、`hotkey{keyCode,modifiers}`、`groupByApplication`、`compactChooser`、`notchEnabled`、`workspaceReferences`、`capabilityProbeResults`。快捷键修饰符使用 Carbon 位掩码，不可直接当作 NSEvent 修饰符。窗口实例、标题、缩略图不落盘。真实 UserDefaults 仅发现主窗口框架位置，不作为业务偏好迁入。

来源的 Exchange 账本另有初始化依据，保留在来源安全归档中；迁移不复制可执行请求到搞操作、不重放旧请求，也不将旧结果当成新验收。

搞锁屏正式安装身份为 `com.gaoseries.GaoSuoPing`，V1.00 / build 1。来源代码中的外观、模拟参数、模拟日志、在场判定及倒计时只在内存，没有业务持久化、UserDefaults、钥匙串或蓝牙绑定。现场未发现 `GaoSuoPing` 业务目录或该 Bundle 的偏好 plist；`GaoSuoPing-Backups` 中存在首装收据。此处的目录不存在与 V1 内存实现一致，不能套用到其他版本或将不可读情况视为空白。用户主动导出的模拟报告不是生产设置或真实锁屏证据，不迁入自动化。目标的锁屏策略不因来源存在而开启。

## 明确导入与冲突处理

仅在用户打开迁移预览后读取来源文件。构造 `LegacyDesktopMigrationSource.standard` 和创建 Importer 不读取来源，不启动旧应用。预览验证 Info.plist 的 Bundle ID、可执行文件名、APPL 类型和受支持版本，并核验来源三份文件、独立身份、schema、代数及摘要。缺失、不可读、损坏、过新、未知字段、重复 JSON 键、符号链接、硬链接和不安全可写权限均拒绝写入。

预览默认保留目标窗口总览偏好。用户明确选择采用来源后，只有尚为默认值的总览区域采用来源的分组、紧凑选择和缩略图偏好，并将 `notchEnabled` 映射为目标 `statusStripEnabled`，保留公开可实现的自有状态条；已有非默认目标设置保留并记录冲突。来源与目标的缩略图排除项只做并集，不移除目标排除。缩略图偏好本身不代表录屏权限或允许读取屏幕；运行功能仍须遵守目标的独立权限与会话控制。

来源热键始终作为待复核 offer，转换后标出与目标启用规则的重叠；导入器不覆盖、不启用、不注册任何热键。目标外观、锁屏策略、输入规则、工作流和其他业务保持原值。工作区 URL 和历史探针只作为私有审计证据保存，不自动启用能力、打开路径或转授旧书签/钥匙串权限。

## 原子提交、幂等与中断恢复

Importer 必须使用 OperationStore 已有的 `LocalData`，不能另建实例并发写同一个目标文件。完整源配置、marker 和 Info.plist 的私有副本及各自摘要存于目标原资料目录的 `legacy-desktop-migration.json`；该文件随目标资料备份，禁止进入公开源码或 Release。

流程为：显示预览 → 用户确认对应 approvalDigest → 重新验证源与目标 → durable prepared journal → 一次原子 settings.json 写入总览和 `desktopMigrationIDs` → 回读 → committed journal。日志包含 sourceID 与 migrationID 映射、来源代数、历史、摘要、冲突和热键 offer。migrationID 由来源身份及内容摘要确定，重复点击和再次启动不会重放导入。

提交前中断且目标未变时，需要用户明确重试并重新验证来源；不会在启动时自动应用。目标已有 receipt、日志尚为 prepared 时，只补齐日志，来源退役后也可恢复。目标已有新改动但没有 receipt 时停止，保留日志与新改动供人工复核；不会用旧整库快照覆盖新资料。receipt 缺少日志、日志缺失/损坏/过新及来源映射不一致时停止写入。

若设置提交后日志写入失败，Importer 抛出 `LegacyDesktopCommittedImportError`，携带设置提交后已经精确回读的 `committedSettings`。调用方须采用该值更新界面内存，并保留存储阻断/恢复提示；不能把调用前的旧 settings 写回。普通尚未确认提交的失败，才尝试通过原 LocalData 读取实际设置；若存储已阻断则保持停写，不能推测提交成功。Importer 不执行真实资料回滚、来源删除或卸载。

## 隔离验证入口

`runLegacyDesktopMigrationTests()` 使用临时 `.noindex` 目录中的合成设置和普通 Info.plist 证据目录，不创建 App、不访问真实来源、不启动 GUI、不触发系统权限、锁屏或蓝牙操作。覆盖来源格式与摘要、缺失/过新/损坏拒写、偏好和热键冲突、事务故障、幂等、来源退出后的 receipt 恢复及不覆盖新目标设置。

完整安全备份及恢复演练、实际主要业务和组件验收、唯一安装入口、公开发布回下载，以及来源最终停写、归档和退役由协调流程另行验证；语法或编译通过不能替代这些条件。
